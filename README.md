## 💳 Что происходит при покупке

1. Покупатель открывает `purchase.html` и переходит к платёжной форме Robokassa.
2. Сервер создаёт заказ. Способ оплаты (например, банковская карта или СБП) зависит от доступных методов на стороне платёжной формы.
3. После подтверждения платежа покупатель получает **личный код доступа**.
4. На странице `game.html` код проверяется сервером. Только после этого браузер получает полные колоды.

На сайте указана цена **499 ₽**. Реальные платежи должны быть отдельно разрешены в настройках сервера. Исходный код сайта сам по себе не подтверждает, что приём платежей включён.

## 🧑‍💻 Локальный просмотр

Сайт статический: сборщик и `npm install` не нужны.

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000/index.html`. Вёрстка и бесплатная демонстрация доступны без бэкенда. Покупка, проверка кода и платные карточки требуют работающего API.

## 🚀 Публикация

Сайт рассчитан на GitHub Pages. Убедитесь, что опубликованы `index.html`, `game.html`, `app.js`, `app.css`, `purchase.html` и `offer.html`, а пути между страницами остаются относительными. После изменения JS или CSS проверьте обновление файлов в браузере.

В `app.js` и `purchase.html` указан адрес серверного API; при смене домена Railway его нужно синхронно обновить. В бэкенде разрешён конкретный origin сайта через CORS. Настройку сервера см. в [vdvoem-pay-server](https://github.com/gudush03-cell/vdvoem-pay-server).

### События аналитики

Файл `analytics.js` **не отправляет данные на сторонние серверы**. Он публикует события `vdvoem:analytics` в браузере и, если уже существует `window.dataLayer`, добавляет записи `vdvoem_*` в эту очередь. Счётчик и пользовательское согласие на аналитические cookies должны быть настроены отдельно до реального сбора метрик.

| Событие | Что означает |
| --- | --- |
| `demo_start` | Нажата кнопка открытия демо |
| `demo_complete` | Пройдено 6 карт, показано предложение полной игры |
| `checkout_click` | Переход со страницы сайта к экрану покупки |
| `checkout_view` | Открыта страница покупки |
| `checkout_start` | Нажата кнопка создания заказа |
| `payment_redirect` | Сервер создал заказ и вернул адрес оплаты |
| `purchase_confirmed` | Сервер вернул статус paid и код; **может быть тестовой оплатой** |
| `telegram_open` | Нажат переход в Telegram-бот |

Для достоверных **покупок и выручки** нужен серверный учёт успешных реальных платежей, исключающий тестовые транзакции и дубли. Клиентское событие `purchase_confirmed` нельзя считать доказательством реального списания.

### Проверки перед включением реальной оплаты

1. Убедиться, что в Robokassa отключён тестовый режим и сумма заказа соответствует 499 ₽.
2. Проверить webhook / callback подтверждения платежа и защиту от повторной обработки.
3. Протестировать выдачу кода, копирование, ввод, повторный вход и восстановление доступа.
4. Проверить чек самозанятого (НПД), контакты поддержки и сценарий возврата.
5. Опубликовать и согласовать отдельную политику обработки персональных данных, как предусмотрено проектом оферты.
6. Проверить адаптивность на телефонах, клавиатуру, доступность кнопок и полное прохождение демо.
